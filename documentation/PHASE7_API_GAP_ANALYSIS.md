# CampusFix Phase 7 — API Gap Analysis and Contract Design

## Repository state and verification limits

The backend is a Core PHP router/controller/service/model application using PDO/MySQL. Flutter uses Dio, Riverpod, secure storage, and GoRouter. The admin directory now contains a React/Vite app. The database directory has only `2026_11_05_password_recovery.sql`; no base schema or test harness is present. Existing tracked mobile Phase 5 changes were already in the workspace and are preserved.

The available source identifies the following database columns and relations: `users` (including `token_version`), `complaints`, `complaint_assignments`, `complaint_status_history`, `complaint_images`, `departments`, `locations`, `feedback`, and `notifications`. No database connection, PHP/Composer, Dart/Flutter, or installed React dependencies are available in this environment, so migration execution, DB-backed API verification, and platform builds cannot be claimed.

## Feature-to-API compatibility matrix (pre-implementation)

| Feature | Existing API/client state | Gap / security | Proposed or retained contract |
| --- | --- | --- | --- |
| Student own complaints/details | `GET /api/complaints/my`, `GET /api/complaints/show?id`; STUDENT-only, query binds authenticated ID | Ownership enforced in model. Images are only DB paths, not served. | Preserve routes and response envelopes; add authenticated image route scoped to complaint access. |
| Complaint submission/images | `POST /api/complaints`; JSON or multipart; `images[]`, max 5, 5 MB each, JPEG/PNG/WebP validated by MIME and image decoder | Files stored under backend storage outside public. Existing mobile picker checks suffix and size but backend remains authoritative. | Preserve upload contract; add image delivery by image ID, never path. |
| Feedback | `POST /api/feedback`, `GET /api/feedback/my`; STUDENT-only, owner and resolved-state checks, one feedback per complaint | Admin list controller passes `limit`, model consumes `per_page`; UI page-size contract inconsistent. | `GET /api/admin/feedback` accepts `per_page` (1..100); keep `limit` alias for compatibility, preferring explicit `per_page`. |
| Staff assignment/status | `GET /api/staff/complaints/my`, `PATCH /api/staff/complaints/status`; STAFF-only; model checks latest assignment and transition | Staff list lacks location, status history, resolution details, and authorized image access. | Add `GET /api/staff/complaints/show?id={complaint_id}`. STAFF; current latest assignee only; `{complaint, images:[{image_id}], status_history}`. Add scoped image endpoint below. Existing update status contract and transitions remain unchanged. |
| Admin student management | Not registered | No list/detail/account status; user model already separates roles and profile queries omit hashes. | `GET /api/admin/students?search=&is_active=&page=&per_page=`; `GET /api/admin/students/show?id=`; `PATCH /api/admin/students/status` JSON `{student_id,is_active}`. ADMIN only. Only selected non-secret fields; status change bumps token version. |
| Admin staff creation/edit | List/detail/status only | No create/edit operation; account fields and departments exist. | `POST /api/admin/staff` JSON `{full_name,email,password,phone?,department_id,employee_id}`; `PATCH /api/admin/staff/update` JSON `{staff_id,full_name,email,phone?,department_id,employee_id}`. ADMIN only. Password min 8 and hashed; role fixed STAFF; no password/hash in response. |
| Admin complaint status | Assignment sets ASSIGNED; staff transitions ASSIGNED→IN_PROGRESS→RESOLVED | No admin status endpoint. Existing history table can audit status changes. | `PATCH /api/admin/complaints/status` JSON `{complaint_id,status,remarks?}`. ADMIN only. Allowed transitions: SUBMITTED→UNDER_REVIEW or REJECTED; UNDER_REVIEW→REJECTED; RESOLVED→CLOSED. Rejection remarks required, max 2000. Row-locked update and history insert. Other transitions remain staff/assignment responsibilities. |
| Admin complaint priority | Listing filter only; priority stored on complaint | No update operation/history. | `PATCH /api/admin/complaints/priority` JSON `{complaint_id,priority}` where priority is LOW/MEDIUM/HIGH/URGENT; ADMIN only; reject CLOSED/REJECTED. Add append-only `complaint_priority_history` table and record previous/new values and admin ID. |
| Department deletion | Create/update/list; related `users.department_id`, `complaints.department_id` | Hard delete could orphan or invalidate history. | Safe delete only when no staff or complaints reference department. `DELETE /api/admin/departments/delete?id=`; ADMIN; lock department, check relations, return 409 when referenced. Locations are not deletable because complaints reference locations and no archival policy exists. |
| Complaint images | Upload and DB image path only | No public route. Exposing arbitrary paths is unsafe. | `GET /api/complaints/image?id={image_id}`; bearer-authenticated ADMIN, owning STUDENT, or current latest-assignee STAFF only. Stream verified image MIME from canonical path under complaint image storage; no filesystem path in response. |
| Notifications | Authenticated user-scoped GET/read/read-all/delete | No admin broadcast requirement established; current-admin inbox is usable. | Keep user-scoped routes. No admin-wide feed or broadcast implemented absent a product requirement and recipient/retention rules. |
| Logout/revocation | Auth middleware checks `users.token_version`, but no logout route. | UI-only logout leaves JWT valid until expiry. | `POST /api/auth/logout` bearer-authenticated, any role, increments token_version for subject; current token immediately fails subsequent authentication. |
| CORS | Front controller has no CORS handling. | Local Vite/browser calls fail cross-origin; wildcard production CORS unsafe. | Add exact-origin allow list from `CORS_ALLOWED_ORIGINS`, answer OPTIONS, allow Authorization/Content-Type and required methods, never enable credential cookies or wildcard origins. |

## Database and rollback plan

Only priority audit history needs a new table. Migration `2026_11_10_complaint_priority_history.sql` creates an InnoDB table with `priority_history_id`, `complaint_id`, `changed_by`, `old_priority`, `new_priority`, `changed_at`; FK references use the existing `complaints.complaint_id` and `users.user_id` columns and cascade only when the parent is removed. The reverse migration `2026_11_10_complaint_priority_history.down.sql` drops that table. Do not run either migration until the deployed base schema and constraint names/types are checked; no database is available here. All other proposed changes use columns/tables already referenced by existing models, especially the previously introduced `users.token_version`.

## Error and compatibility policy

New JSON endpoints use existing `{success,message,data}` envelopes. Malformed/invalid fields return 422, missing/expired/revoked auth 401, role denial 403, absent resources 404, and business conflicts (duplicate email, referenced department, invalid status/priority state) 409. Existing endpoint paths and fields remain valid. Admin-only changes call `authorize(['ADMIN'])` in the controller; ownership checks use the authenticated subject, never a client-supplied student/staff identity. The binary image endpoint is the exception to JSON and returns 404/401/403 without disclosing file paths.

## Implementation and verification status

The routes and client integrations described above are implemented in source. This is a source-level contract audit only: no live MySQL schema or running API was provided, and the local environment has no PHP/Composer, Dart/Flutter, or installed React dependencies. The admin `npm test` command runs successfully but discovers zero tests; lint, typecheck, and Vite build cannot run until dependencies are installed. Thus endpoint runtime behavior and the SQL migration remain unverified.

The backend API smoke script is `campusfix-backend/tests/api_security_smoke.php`. Run it against a disposable/local database and API with `CAMPUSFIX_TEST_BASE_URL`, `CAMPUSFIX_TEST_STUDENT_TOKEN`, `CAMPUSFIX_TEST_STAFF_TOKEN`, `CAMPUSFIX_TEST_ADMIN_TOKEN`, `CAMPUSFIX_TEST_STUDENT_ID`, `CAMPUSFIX_TEST_FOREIGN_COMPLAINT_ID`, and `CAMPUSFIX_TEST_UNASSIGNED_COMPLAINT_ID` set to dedicated test fixtures. Optionally set `CAMPUSFIX_TEST_LOGOUT_TOKEN` to a disposable token; the script revokes it. The required complaint fixtures must belong to another student and to no current assignment for the staff account, respectively. The script is read-only except for the optional logout check.
